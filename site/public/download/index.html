Updates

How the installed app checks for updates

The app checks on its own, asks you before it changes anything, and never sends anything about you.

What happens

  • ✓It reads one small file, /download/updates.json, which names the newest published version, its release date, its notes and a link to the release page.
  • ✓It compares that with the version of the copy you are running. There are three answers and no fourth: you are up to date, a newer version exists (with the version, the date, the notes and a link), or the check could not be completed, with the reason.
  • ✓The link is only ever an https page on this site or on github.com. A file that points anywhere else is refused, and the app says the check could not be completed instead of showing it.

How often, and what it asks

  • ✓Every 6 hours at most, plus whenever you press Check for updates in the app. Nothing else triggers it.
  • ✓The request carries no identifiers: no account, no install id, no machine name, no version, no query string. One header, Accept: application/json, on one URL, the same thing an anonymous visitor's browser sends.
  • ✓It is one small file and it gives up after five seconds. A failed check is reported as a failed check; it is not retried in a loop.

When there is a new version

  • ✓It asks first. You get Update and restart, Later or Skip this version. Nothing is downloaded or installed until you choose Update and restart.
  • ✓Then it downloads the file for your system from the GitHub release, and refuses it unless its SHA-256 matches the one in updates.json. It installs over your current copy in the same folder and reopens the app. Your chats, settings and keys stay where they are.
  • ✓The in-app update doesn't trigger "Windows protected your PC" or the Mac warning again. Those only appear for files a browser downloaded.
  • ○Version 0.1.0 came out before the updater. It shows the release page instead, so 0.1.0 users install the next version by hand once. From then on it updates itself.
  • ✓The update check itself sends nothing back: no "checked for updates" ping. A check is an ordinary request for a static file, indistinguishable from someone loading this page.

Before you download

What a download will and will not do

So you know what you are getting before you run it.

Windows

  • ✓The window, the model picker, the router, the plugins and the subagents all run here today, on my machine.
  • ✓Built: an NSIS installer and a portable single file, both 64-bit, both from the release pipeline. Sizes and checksums are in the table at the bottom of this page.
  • ○Unsigned: there is no code-signing certificate yet, so Windows shows "Windows protected your PC" once. Choose More info, then Run anyway.
  • ✓Setup or portable? Setup is the normal download: it installs once, adds a Start menu entry, keeps your settings in one place and updates itself from inside the app. Because the installed file no longer carries the browser's mark, that first "Windows protected your PC" warning does not come back for updates. The portable single file needs no install and can live on a USB stick, but it gets the warning again on each newly downloaded copy, and it cannot update itself.
  • ○Voice input needs a Python runtime; it stays a separate, optional download.

macOS

  • ✓Built: a disk image and a zip for Apple silicon, and the same two for Intel, produced by the macOS job in the release pipeline. A Mac build can only be produced on a Mac, which is why that is a separate job.
  • ○Unsigned and not notarized: there is no Apple Developer certificate yet, so macOS quarantines the download and refuses the first launch. Right-click the app, choose Open, then Open again, or run once: xattr -dr com.apple.quarantine "/Applications/Rosalena Harness.app"
  • ○Nobody has opened it on a Mac yet. The native title bar (traffic lights, native drag and zoom, an app menu with Quit) and the real icon are in the build and covered by tests, but no Mac has run this app, and this page will not pretend otherwise.

Linux

  • ✓Built by the release pipeline's Linux job: an AppImage that runs on most distributions and a .deb for Debian and Ubuntu, both 64-bit (x86_64), first released in 0.1.14.
  • ○Unsigned. AppImage: run chmod +x on the file, then open it. Ubuntu 22.04 and newer need FUSE 2 for AppImages: sudo apt install libfuse2t64 on 24.04, libfuse2 on 22.04. .deb: sudo apt install ./ followed by the file name.
  • ✓The AppImage updates itself from inside the app, the same way the Windows installer does. A .deb install updates by installing the next .deb from this page.
  • ○Nobody has opened it on a Linux desktop yet. It is built and tested in the pipeline, but this page will not claim more than that.

Every platform

  • ✓The app starts the local router itself when nothing is already listening on 8077, waits for it before showing the window, and stops the one it started when you quit. If you already run a router by hand, yours is used and nothing new is started. The router ships with the app, so there is no Node install to do.
  • ✓No account, no bundled model. The free cloud models work on any 64-bit machine.
  • ✓Your files and keys stay on your machine. Chats on cloud models are shared with me while sharing is on (the default); one click in Settings turns it off.
What it needs

What you'll need to run it

You don't need a big graphics card to start. The free cloud models work on any 64-bit PC. To run a model on your own machine, more graphics memory means a bigger model. The 27B model I use takes about 20 GB on an RTX 3090.

Optional

Let the agent use your own browser

Rosalena can read pages in your own browser with your logins, and click and type there, even inside embedded frames. That goes through SolBrowser, a small extension I built. It isn't on the Chrome Web Store yet, so you load it yourself once: in the app, Settings > Your browser > Set up does most of it, and the app asks you the first time the agent needs it. You only need it for sites you're signed in to; public pages are read without a browser at all.
